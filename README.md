# AI 产品拆解 Skill

给出 AI 产品链接，自主调研和体验，输出有证据的 Markdown 深度报告，帮助做功能与交互设计决策。

分析优先级是：**功能与交互 → 产品定位 → 技术架构 → 商业策略**。也可用于求职作品集、对外发布和学习研究。有自己的产品背景时，建议会围绕该背景展开；只提供被拆产品链接时，报告会提炼可迁移的设计与适用条件。

## 快速使用

将仓库克隆到本机 Codex 技能目录中；已有同名技能时先比较内容，不要直接覆盖。

```bash
git clone https://github.com/weiweidounais/ai-product-teardown.git "$HOME/.codex/skills/ai-product-teardown"
```

仓库为公开仓库，可直接查看和克隆。

在能读取该技能的 Codex 会话中使用：

```text
使用 $ai-product-teardown 拆解这个产品：https://产品网址
```

需要针对自己的产品做决策时，可以补充：

```text
使用 $ai-product-teardown 拆解这个产品：https://产品网址

我的产品面向小型电商团队，主要帮助制作商品视频。
我正在决定是否加入自动生成后的局部修改功能。
重点分析输入引导、生成过程反馈、局部修改和交付衔接。
```

以上是调用示例，不是已经完成的产品研究。

## 它会怎样拆

| 阶段 | 关注点 | 主要产出 |
|---|---|---|
| 产品介绍 | 谁用、什么任务、交付什么 | 产品与研究范围 |
| 场景体验与评测 | 用户能否完成真实任务 | 编号截图、成品检查、用户旅程、异常覆盖 |
| 差异化定位 | 替代什么旧流程，差异在哪里 | 定位与替代方案比较 |
| 六层拆解 | 市场、商业、场景与用户、技术、模型、基础 | 分层分析与人机分工 |
| 架构总结 | 各层如何共同完成任务 | 五层架构图与技术流程图 |
| 设计启发 | 哪些设计适合借鉴，代价是什么 | 建议、适用条件与验证办法 |

六层拆解保留案例的分析顺序，五层架构图用于最后汇总。两者的映射及具体规则见[解释与注释文章](docs/skill-guide.md)。

## 证据与体验边界

- **页面事实**：直接观察或原文可确认的内容，区分亲测和官方声明。
- **合理推断**：写出事实依据与推导理由，不冒充产品内部实现。
- **尚未确认**：保留缺口与补测办法，不用常识填空。

默认在可核实的免费额度内自主体验。需要用户协助登录、购买或使用付费额度时，暂停相关操作，继续其他研究，并交付已完成部分和待补测项。实际能否体验取决于浏览器工具、产品可访问性、账号及额度。

技术分析默认到架构与机制，不生成内部 Schema、接口定义或提示词草案。评分依据产品类型和实际观察调整；证据不足时用定性评测。

## 文件结构

```text
ai-product-teardown/
├── SKILL.md                         # 触发说明、默认行为和主流程
├── agents/
│   └── openai.yaml                  # 技能展示名称和示例调用
├── references/
│   ├── research-and-testing.md      # 调研、体验、证据和评测细则
│   └── report-template.md           # 报告骨架、表格和交付自检
├── docs/
│   └── skill-guide.md              # 面向使用者与维护者的解释、逐段注释
└── README.md
```

运行时入口是 `SKILL.md`，两个参考文件按研究阶段读取；说明文章用于理解和维护，不是额外的执行步骤。

默认报告保存在当前工作区：

```text
artifacts/ai-product-teardown/产品标识-日期/
├── report.md
└── evidence/                        # 仅保存实际采集的证据文件
```
